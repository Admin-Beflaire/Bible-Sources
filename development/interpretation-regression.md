# Contextual interpretation verification — 0.1.20

## Design limitations identified

The previous Preview supplied broad explain/review instructions without a concrete discovery process. The runtime still preferred the owner's working framework. Standard/Detailed default research limits and local-history deferral could suppress evidence needed to distinguish readings; focused source restrictions did not explicitly disable secondary research. Full word-study guidance was also bundled into every passage's exegesis/canonical part. Some runtime documents still described Next as passage-only despite the staged Worker contract.

## Implementation

`cloudflare/src/interpretation.js` constructs a passage-independent active-part research contract and compact output requirements. It uses no passage matching, preset interpretations, model call or external request. Local exegesis asks for an independent ambiguity/discovery pass, serious-case admission, language/construction checks, supporting arguments, objections, cumulative reasoning and explicit gaps. Relevant history may inform local interpretation; the later history part develops only remaining questions. Canonical synthesis preserves disputed premises. Translation keeps its own narrow consequential checks and one defensible main rendering. No new validation call or handoff is added.

Runtime skills and method policy no longer prefer an owner framework. Interpretation cases cannot use percentages, likelihood labels, rankings or a preferred winner; explicit textual claims and unequal evidence remain clear. A later directive theological synthesis is separate. Focused restrictions explicitly exclude secondary/external research. Word-study detail moves to an on-demand reference. Runtime continuation guidance defers to active part boundaries.

## Automated and live checks

Tests use the three neutral acceptance prompts and an unrelated Mark passage to check reusable routing, exact ranges, depth, source restrictions, part boundaries, Ready/Next continuity, zero planning asset reads, packet bounds and development-answer exclusion. Protocol checks initialize the actual local authenticated Worker and exercise its tools. Existing source, Genesis, authentication/public boundaries and Python/Worker parity checks remain required. These tests do not generate or judge exegesis.

Live connected Preview checks must repeat the neutral plans, inspect later-part contracts and retrieve actual primary/lexical evidence. Check the Genesis index, timestamps and failure packets. Record the release source, successful Cloudflare Preview build and unchanged Production/Public deployment IDs. The code commit and later documentation-only verification commit may differ.

The before/after `benchmark-delivery.mjs` replays use identical queries, editions, format, language and five cold/warm repetitions per case on the same Node runtime. They measure local planning/retrieval/readiness overhead only. They do not run a host model, include network latency, measure Cloudflare CPU or establish faster study generation. Planning-payload size is measured; avoid interpreting timing noise as an improvement.

- `Full study Genesis 9:18-27, exact`
- `Full study Judges 11:29-40, exact`
- `Full study Romans 8:1-39, exact`

Continue each study with `Next` until all four parts are delivered. Do not supply the rubric or expected interpretations. Record host/model/client, deployed version, source/tool trace, outputs and observed timing. Review actual arguments, language, sources and objections against every criterion; keyword presence, a model self-rating or a passing server test cannot establish success. Repeat proportionate Standard and source-restricted variants. A study generated in this development conversation is not blind because the expected cases are already visible to this model.

No independent host-model runner is provided by this MCP server or the available development tools. Unless a real fresh-host run is separately captured, report host acceptance as unverified rather than claiming the discovery goal is demonstrated. Never bypass Access, introduce a model provider or chargeable inference service merely to produce a test result.
